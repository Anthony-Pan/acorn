# v1.1 — wiring Apple Shortcuts + Services into the build

The Swift code in `apple-shortcuts/` is ready. This doc captures the
end-to-end pipeline that lights it up once v1.1 ships code signing and
notarisation.

## Prerequisites

- Apple Developer Program membership (USD $99/year).
- `Developer ID Application: Onyxcraft (TEAMID)` certificate installed in
  the macOS login keychain.
- An app-specific password stored in the keychain profile `acorn-notary`:
  ```sh
  xcrun notarytool store-credentials acorn-notary \
    --apple-id "you@example.com" \
    --team-id  "ABCDE12345" \
    --password "your-app-specific-password"
  ```
- macOS 14.0 SDK (Xcode 15+). App Intents requires macOS 13 minimum, but
  the build host should be on 14+ to compile the manifest cleanly.

## Build pipeline

### 1. Build the Swift package

From the repo root:

```sh
cd apple-shortcuts
swift build -c release
```

Outputs `libAcornIntents.a` and `AppIntents.swiftmodule` under
`.build/release/`. The static archive is what the Tauri bundle links
against.

### 2. Add the link step to `src-tauri/build.rs`

The current `build.rs` only forwards to `tauri_build::build()`. Replace it
with:

```rust
fn main() {
    #[cfg(target_os = "macos")]
    {
        println!("cargo:rustc-link-search=native={}", concat!(
            env!("CARGO_MANIFEST_DIR"), "/../apple-shortcuts/.build/release"
        ));
        println!("cargo:rustc-link-lib=static=AcornIntents");
        println!("cargo:rustc-link-lib=framework=AppIntents");
        println!("cargo:rustc-link-lib=framework=AppKit");
    }
    tauri_build::build();
}
```

### 3. Register the intents at startup

In `src-tauri/src/lib.rs`, after `app.manage(database)`, add a Rust → Swift
boundary. The Swift side exposes a `@_cdecl` function:

```swift
@_cdecl("acorn_register_app_intents")
public func acornRegisterAppIntents() {
    Task { @MainActor in
        AcornServices.register()
    }
}
```

The Rust side calls it:

```rust
#[cfg(target_os = "macos")]
unsafe extern "C" {
    fn acorn_register_app_intents();
}

#[cfg(target_os = "macos")]
{
    unsafe { acorn_register_app_intents() };
}
```

### 4. Add the Services menu entries to `Info.plist`

In `src-tauri/tauri.conf.json` → `bundle.macOS`, add:

```json
"infoPlist": {
  "NSServices": [
    {
      "NSMenuItem":   { "default": "Stash to Acorn" },
      "NSMessage":    "stashSelectedText",
      "NSPortName":   "Acorn",
      "NSSendTypes":  ["NSStringPboardType", "public.utf8-plain-text"]
    }
  ]
}
```

(Tauri 2 supports `infoPlist` as either a path or an inline object.)

### 5. Codesign and notarise

```sh
pnpm tauri build

xcrun codesign \
  --sign "Developer ID Application: Onyxcraft (TEAMID)" \
  --options runtime \
  --timestamp \
  --deep \
  "src-tauri/target/release/bundle/macos/Acorn.app"

ditto -c -k --sequesterRsrc --keepParent \
  "src-tauri/target/release/bundle/macos/Acorn.app" Acorn.zip

xcrun notarytool submit Acorn.zip \
  --keychain-profile acorn-notary \
  --wait

xcrun stapler staple "src-tauri/target/release/bundle/macos/Acorn.app"
```

The same DMG produced by the existing release workflow gets the same
treatment — see `.github/workflows/release.yml`.

### 6. Verify

```sh
# 1. Open the signed app once so macOS registers its App Intents and Services.
open "src-tauri/target/release/bundle/macos/Acorn.app"

# 2. Confirm Shortcuts.app discovers the intents.
open -a Shortcuts
# Look for "Stash with Acorn", "Summon Acorn", "Open Acorn" under
# Apps → Acorn.

# 3. Confirm Services menu picks up "Stash to Acorn".
#    Select text in any app → right-click → Services → Stash to Acorn.

# 4. Confirm "Hey Siri, stash with Acorn" works on a Mac with Siri enabled.
```

### 7. Submit to Homebrew Cask

With the bundle signed + notarised, the official-cask submission in
`homebrew/homebrew-cask-submission/` is finally ready to go. See
`homebrew/homebrew-cask-submission/SUBMISSION.md`.

## CI hookup

Add a `swift-build` job to `.github/workflows/release.yml` that runs on
macOS runners before the `tauri-action` step. It produces the
`libAcornIntents.a` archive and uploads it as a workflow artifact so the
Tauri build step can link against it.

A draft of that workflow change lives at the end of this document — copy
it into `.github/workflows/release.yml` when wiring v1.1.

```yaml
  swift-build:
    runs-on: macos-latest
    steps:
      - uses: actions/checkout@v4
      - run: cd apple-shortcuts && swift build -c release
      - uses: actions/upload-artifact@v4
        with:
          name: acorn-intents-${{ runner.arch }}
          path: apple-shortcuts/.build/release/libAcornIntents.a

  build:
    needs: swift-build
    ...
    steps:
      ...
      - uses: actions/download-artifact@v4
        if: matrix.os == 'macos-latest'
        with:
          name: acorn-intents-${{ runner.arch }}
          path: apple-shortcuts/.build/release/
      ...
```

## Rollback plan

If the Swift bundle fails to link or notarise close to release time, the
fallback is unchanged from v1.0: ship without the App Intents, leave the
`acorn://` URL scheme as the only Shortcuts entry point, push the v1.1
notes one version. The Swift source stays in tree — no need to rip it out.
